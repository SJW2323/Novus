# Novus

An AI tutor for A-level Biology that students talk to like a video call. Anam
renders the face and voice; Claude is the brain deciding what the tutor says;
Supabase stores accounts and the per-student learning memory that makes each
session more personalized than the last.

## Stack

- Next.js 16 (App Router, TypeScript, Tailwind, shadcn/ui on Base UI)
- Supabase (Postgres + Auth + RLS)
- Anthropic Claude (`@anthropic-ai/sdk`) — the tutor's brain
- Anam AI (`@anam-ai/js-sdk`) — the realistic talking avatar, driven entirely
  by Claude's text via `anamClient.talk()` (Anam's own LLM is disabled)

## One-time setup

### 1. Supabase

1. Create a project at [supabase.com](https://supabase.com).
2. In the SQL editor, run `supabase/migrations/0001_init.sql` then
   `supabase/migrations/0002_seed_aqa_biology.sql`.
3. In **Authentication → Providers**, disable email confirmation for local
   testing (Settings → Auth → "Confirm email" off), otherwise `/signup` won't
   get a session back immediately. Re-enable it before going to real users.
4. Copy **Project Settings → API**: `Project URL`, `anon public` key, and
   `service_role` key (keep this last one secret).

### 2. Anthropic

Get an API key from [console.anthropic.com](https://console.anthropic.com).

### 3. Anam

1. Get an API key from the [Anam dashboard](https://anam.ai).
2. Pick a stock avatar and voice in the dashboard (Personas/Avatars section)
   and copy their IDs — these go in `ANAM_AVATAR_ID` / `ANAM_VOICE_ID`.
3. The persona's `llmId` is hardcoded to `CUSTOMER_CLIENT_V1` in
   [`src/lib/anam.ts`](src/lib/anam.ts), which disables Anam's own LLM —
   every reply is instead generated by Claude and pushed to the avatar via
   `talk()`. If Anam has changed this special value since, that's the first
   thing to check if the avatar goes silent or talks over Claude.

### 4. Environment variables

```
cp .env.local.example .env.local
```

Fill in all six values (Supabase URL/anon/service-role, Anthropic key, Anam
key/avatar/voice).

### 5. Run it

```
npm install
npm run dev
```

Visit `localhost:3000`, sign up, and start a session from `/dashboard`.

## How a session works

1. `/tutor` calls `POST /api/session/start`, which loads the student's
   `learning_profile` + `student_topic_mastery` from Supabase, builds a
   system prompt for Claude, and mints an Anam session token bound to that
   prompt (mostly vestigial since Anam's LLM is off, but required by its API).
2. The browser opens an Anam WebRTC session and listens for
   `MESSAGE_STREAM_EVENT_RECEIVED` events where `role === MessageRole.USER`
   and `endOfSpeech` is true — that's Anam's own speech-to-text handing us a
   finalized line from the student.
3. That text goes to `POST /api/tutor/turn`, which calls Claude with the
   running transcript + the student's memory, saves both sides of the
   exchange to `session_messages`, and returns Claude's reply.
4. The browser calls `anamClient.talk(reply)` and the avatar speaks it.
5. On hangup, `POST /api/session/end` runs one summarization call over the
   full transcript and upserts `learning_profile` and
   `student_topic_mastery` — this is what the next session's system prompt
   reads back in step 1.

## Known gaps (by design, for this prototype pass)

- No billing/payments.
- No parent view or admin surface.
- Topic-name matching between Claude's summarization output and
  `syllabus_topics` is a case-insensitive exact match — good enough for a
  demo, not typo-proof.
- Only AQA A-level Biology is seeded; OCR/Edexcel topic rows aren't in yet.
